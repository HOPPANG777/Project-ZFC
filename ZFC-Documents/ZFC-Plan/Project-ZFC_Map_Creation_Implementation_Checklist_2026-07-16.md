# Project-ZFC 맵 생성 구현 체크리스트

작성일: 2026-07-16  
대상: Project-ZFC 콘솔 프로토타입의 검증된 맵 생성 파이프라인  
설계 근거: [Project-ZFC 맵 생성 계약과 소유권 설계 학습 정리](Project-ZFC_Map_Creation_Design_Study_2026-07-16.md)  
선행 설계: [Project-ZFC 맵 시스템 설계 학습 정리](Project-ZFC_Map_Design_Study_2026-07-13.md)

## 1. 이번 구현 범위

이번 구현의 목표는 다음 파이프라인을 완성하는 것이다.

```text
TileGrid
-> MapFactory 구조 검증
-> TileLayout
-> Map
-> MapCreationResult
-> unique_ptr<Map> 소유권 전달
```

이번 단계에 포함하지 않는 기능:

- 절차적 방 생성 알고리즘 완성
- 플레이어와 적 배치
- 유닛 점유 검사
- 공격 예고와 위험 타일
- 전투 턴 처리
- 콘솔 문자 렌더링
- 그래픽 API와 스프라이트
- 맵 파일 저장과 불러오기

## 2. 완료 조건

- [ ] 외부에서 빈 `Map`을 생성할 수 없다.
- [ ] 외부에서 원시 `TileGrid`로 `Map`을 직접 생성할 수 없다.
- [ ] 외부에서 `TileLayout`을 직접 생성할 수 없다.
- [ ] 잘못된 `TileGrid`는 구체적인 실패 상태를 반환한다.
- [ ] 올바른 `TileGrid`만 `TileLayout`이 될 수 있다.
- [ ] 성공한 `Map`은 `unique_ptr`로 전달된다.
- [ ] 실패 결과에는 `Map`이 존재하지 않는다.
- [ ] 생성 이후 지형을 외부에서 수정할 수 없다.
- [ ] 기존 `Map` 질의 함수가 동일한 계약으로 동작한다.
- [ ] Debug x64와 Release x64에서 빌드된다.
- [ ] 모든 성공 및 실패 테스트를 통과한다.

## 3. 문서 결정 사항 반영

- [ ] 빈 행과 빈 열을 모두 거부한다.
- [ ] 모든 행의 너비가 같아야 한다.
- [ ] 내부 `TILE_NONE`을 거부한다.
- [ ] 맵 저장 구조는 직사각형으로 유지한다.
- [ ] 현재 사용하지 않는 공간은 `TILE_WALL`로 표현한다.
- [ ] 생성 후 지형 수정 인터페이스를 제공하지 않는다.
- [ ] 예상 가능한 후보 탈락과 구조적 계약 위반을 구분한다.
- [ ] 재시도와 대체 맵은 `MapFactory`가 아니라 상위 로딩 흐름이 담당한다.
- [ ] 그래픽 자원 검증을 맵 구조 검증에 포함하지 않는다.

## 4. TileGrid 정의 분리

권장 파일:

- `ZFC-Console/Map/TileGrid.h`

작업:

- [ ] 현재 `Map.h`에 있는 `TileRow` 별칭을 이동한다.
- [ ] 현재 `Map.h`에 있는 `TileGrid` 별칭을 이동한다.
- [ ] `TileGrid.h`가 `TileType` 정의를 알 수 있게 한다.
- [ ] `TileGrid.h`에는 생성, 검증, 렌더링 기능을 넣지 않는다.
- [ ] `Map.h`가 새로운 `TileGrid.h` 위치를 사용하도록 변경한다.
- [ ] 다른 파일이 `Map.h`를 거치지 않고 `TileGrid`를 사용할 수 있게 한다.

책임 확인:

```text
TileGrid
-> 검증 전 원시 컨테이너 표현
-> 생성 중 수정 가능
-> 자체적으로 유효성을 보장하지 않음
```

## 5. TileLayout 타입 작성

권장 파일:

- `ZFC-Console/Map/TileLayout.h`
- 필요한 경우 `ZFC-Console/Map/TileLayout.cpp`

책임:

- [x] 내부에 `TileGrid`를 소유한다.
- [ ] 검증 성공 후의 타일 배치만 표현한다.
- [ ] 단순 타입 별칭이 아닌 별도 타입으로 만든다.
- [ ] 기본 생성 경로를 금지한다.
- [ ] 외부 직접 생성 경로를 제한한다.
- [ ] `MapFactory`만 정상 생성할 수 있게 한다.
- [ ] 생성 이후 행 추가 및 제거 기능을 제공하지 않는다.
- [ ] 생성 이후 개별 타일 변경 기능을 제공하지 않는다.
- [ ] 내부 `TileGrid`의 수정 가능한 참조를 반환하지 않는다.
- [ ] `Map`이 크기와 타일을 읽는 데 필요한 최소 접근만 제공한다.
- [ ] 콘솔 문자나 그래픽 자원 정보를 포함하지 않는다.

복사와 이동:

- [ ] 기본 생성 금지 여부를 선언에 반영한다.
- [ ] 복사 금지 여부를 선언에 반영한다.
- [ ] 이동 가능 여부를 선언에 반영한다.
- [ ] 현재 정책은 복사 금지, 이동 허용을 우선 검토한다.
- [ ] 불필요한 사용자 정의 소멸자를 작성하지 않는다.

불변 조건:

- [ ] 높이가 0보다 크다.
- [ ] 너비가 0보다 크다.
- [ ] 모든 행의 너비가 같다.
- [ ] 모든 내부 타일이 유효하다.
- [ ] 내부에 `TILE_NONE`이 없다.

## 6. Map 생성 상태 열거형 작성

권장 위치:

- 초기에는 `ZFC-Console/Map/MapCreationResult.h`에 함께 정의
- 열거형이 커지면 별도 파일로 분리

최소 상태:

- [ ] 성공
- [ ] 행 또는 열 없음
- [ ] 행 너비 불일치
- [ ] 내부 `TILE_NONE`
- [ ] 크기 범위 초과

선택 상태:

- [ ] 첫 행의 열 없음
- [ ] 중간 빈 행 발견
- [ ] 지원하지 않는 타일 값
- [ ] 알 수 없는 내부 실패

컨벤션:

- [ ] 열거형 타입 이름은 `PascalCase`를 사용한다.
- [ ] 모든 열거자에 같은 의미의 접두어를 붙인다.
- [ ] 첫 번째 열거자에 `= 0`을 명시한다.
- [ ] 열거자는 `SCREAMING_SNAKE_CASE`를 사용한다.
- [ ] 성공을 첫 값으로 둘지, 상태 없음 또는 알 수 없음을 첫 값으로 둘지 계약에 맞춰 결정한다.

## 7. MapCreationResult 작성

권장 파일:

- `ZFC-Console/Map/MapCreationResult.h`
- 필요한 경우 `ZFC-Console/Map/MapCreationResult.cpp`

보유 정보:

- [ ] 맵 생성 상태
- [ ] 성공한 `unique_ptr<Map>`
- [ ] 필요할 경우 실패한 행 또는 좌표
- [ ] 필요할 경우 생성 시드와 시도 번호

결과 불변 조건:

- [ ] 성공 상태라면 `Map`이 반드시 존재한다.
- [ ] 실패 상태라면 `Map`이 반드시 존재하지 않는다.
- [ ] 성공인데 `Map`이 없는 상태를 만들 수 없다.
- [ ] 실패인데 `Map`이 있는 상태를 만들 수 없다.
- [ ] 부분 생성된 `Map`을 결과에 넣지 않는다.

접근 계약:

- [ ] 호출자가 성공 여부를 읽을 수 있다.
- [ ] 호출자가 실패 상태를 읽을 수 있다.
- [ ] 호출자가 성공한 `Map` 소유권을 한 번 이동받을 수 있다.
- [ ] 외부에서 상태와 포인터를 독립적으로 수정할 수 없게 한다.
- [ ] 소유권을 이동한 뒤 결과가 더 이상 `Map`을 소유하지 않는다는 점을 명시한다.
- [ ] 결과 타입은 복사하지 않고 이동하도록 한다.

## 8. 기존 Map 구조 변경

수정 파일:

- `ZFC-Console/Map/Map.h`
- `ZFC-Console/Map/Map.cpp`

소유 데이터:

- [ ] 기존 `TileGrid tiles` 직접 소유를 제거한다.
- [ ] 검증된 `TileLayout`을 소유하게 한다.
- [ ] 크기 정보를 중복 멤버로 추가하지 않는다.
- [ ] `TileLayout`을 단일 진실 공급원으로 유지한다.

생성 정책:

- [ ] 빈 기본 생성자를 제거하거나 금지한다.
- [ ] 원시 `TileGrid`를 받는 외부 생성 경로를 제공하지 않는다.
- [ ] `MapFactory`가 검증된 `TileLayout`으로만 생성할 수 있게 한다.
- [ ] 테스트 전용 빈 생성자를 별도로 제공하지 않는다.
- [ ] 복사 정책을 명시한다.
- [ ] 이동 정책을 명시한다.

기존 질의 함수:

- [ ] `GetSize()`가 `TileLayout`의 실제 크기를 사용한다.
- [ ] `Contains()`가 직사각형 크기를 기준으로 검사한다.
- [ ] 음수 좌표를 컨테이너 인덱스로 변환하기 전에 차단한다.
- [ ] `TileAt()`이 유효 좌표의 지형을 반환한다.
- [ ] `TileAt()`이 범위 밖에서 `TILE_NONE`을 반환한다.
- [ ] `IsWalkable()`이 `TILE_FLOOR`에만 `true`를 반환한다.
- [ ] 유닛 점유 여부를 `IsWalkable()`에 추가하지 않는다.
- [ ] 공격 예고와 위험 타일을 `Map`에 추가하지 않는다.

불변성:

- [ ] 지형 전체를 수정 가능한 형태로 반환하지 않는다.
- [ ] 개별 타일을 임의로 변경하는 공개 함수를 추가하지 않는다.
- [ ] 문이나 파괴 가능한 벽은 실제 요구가 생길 때 별도 행동 계약으로 검토한다.

## 9. MapFactory 작성

권장 파일:

- `ZFC-Console/Map/MapFactory.h`
- `ZFC-Console/Map/MapFactory.cpp`

책임:

- [ ] 후보 `TileGrid`의 소유권을 전달받는다.
- [ ] 구조 불변 조건을 검증한다.
- [ ] 검증 성공 시에만 `TileLayout`을 생성한다.
- [ ] `TileLayout`으로 `Map`을 생성한다.
- [ ] 완성된 `Map`을 `unique_ptr`로 소유한다.
- [ ] `MapCreationResult`를 통해 성공 또는 실패를 전달한다.
- [ ] 부분적으로 생성된 객체를 외부에 노출하지 않는다.

검증 순서:

1. [ ] 바깥 그리드에 행이 존재하는지 확인한다.
2. [ ] 첫 행에 열이 존재하는지 확인한다.
3. [ ] 높이를 프로젝트 좌표 타입으로 표현할 수 있는지 확인한다.
4. [ ] 첫 행의 너비를 기준 너비로 정한다.
5. [ ] 너비를 프로젝트 좌표 타입으로 표현할 수 있는지 확인한다.
6. [ ] 모든 행의 너비가 기준 너비와 같은지 확인한다.
7. [ ] 모든 내부 타일을 순회한다.
8. [ ] 내부 `TILE_NONE` 존재 여부를 확인한다.
9. [ ] 필요하다면 지원하지 않는 열거형 값을 확인한다.
10. [ ] 모든 검증 성공 후에만 `TileLayout`을 생성한다.
11. [ ] `TileLayout` 성공 후에만 `Map`을 생성한다.
12. [ ] 성공 상태와 `unique_ptr<Map>`을 함께 결과로 만든다.

실패 처리:

- [ ] 첫 실패 원인을 상태로 반환한다.
- [ ] 실패 시 `Map`을 생성하지 않는다.
- [ ] 실패 시 후보 `TileGrid`를 폐기한다.
- [ ] 실패 데이터를 자동 수정하지 않는다.
- [ ] 짧은 행을 WALL로 자동 채우지 않는다.
- [ ] 긴 행을 자동으로 자르지 않는다.
- [ ] 내부 `TILE_NONE`을 WALL로 자동 변경하지 않는다.
- [ ] 구조 오류를 예상 가능한 절차적 후보 탈락으로 조용히 숨기지 않는다.

## 10. 생성 접근 제한 확인

컴파일 단계에서 차단할 경로:

- [ ] 외부 빈 `Map` 생성
- [ ] 외부 빈 `TileLayout` 생성
- [ ] 원시 `TileGrid`를 사용한 `Map` 직접 생성
- [ ] 원시 `TileGrid`를 사용한 `TileLayout` 직접 생성
- [ ] 검증을 우회한 대체 맵 생성
- [ ] 지형 데이터 전체의 수정 가능한 접근

공식 생성 경로:

```text
TileGrid
-> MapFactory
-> TileLayout
-> Map
-> MapCreationResult
-> unique_ptr<Map>
```

## 11. 정상 생성 테스트

기본 테스트 데이터:

- [ ] 크기 `3 x 2`
- [ ] 모든 행의 너비가 같음
- [ ] `TILE_WALL`과 `TILE_FLOOR`가 섞여 있음
- [ ] 내부 `TILE_NONE` 없음

예상 결과:

- [ ] 생성 상태가 성공이다.
- [ ] 결과에 `Map`이 존재한다.
- [ ] `GetSize()`가 `(3, 2)`다.
- [ ] 각 좌표의 `TileAt()` 결과가 입력과 같다.
- [ ] `TILE_FLOOR`만 통행 가능하다.
- [ ] `TILE_WALL`은 통행 불가능하다.

## 12. 빈 크기 실패 테스트

- [ ] 행이 0개인 그리드는 실패한다.
- [ ] 행은 있지만 첫 행의 열이 0개인 그리드는 실패한다.
- [ ] 모든 행이 빈 그리드는 실패한다.
- [ ] 실패 결과에 `Map`이 존재하지 않는다.
- [ ] 실패 상태가 입력 원인을 구분한다.

## 13. 직사각형 실패 테스트

- [ ] 첫 행보다 짧은 행이 있으면 실패한다.
- [ ] 첫 행보다 긴 행이 있으면 실패한다.
- [ ] 중간 행이 비어 있으면 실패한다.
- [ ] 마지막 행의 너비가 다르면 실패한다.
- [ ] 여러 개의 행이 서로 다른 너비를 가지면 실패한다.
- [ ] 실패 결과에 `Map`이 존재하지 않는다.

## 14. TILE_NONE 실패 테스트

- [ ] 첫 좌표에 `TILE_NONE`이 있으면 실패한다.
- [ ] 중간 좌표에 `TILE_NONE`이 있으면 실패한다.
- [ ] 마지막 좌표에 `TILE_NONE`이 있으면 실패한다.
- [ ] 여러 `TILE_NONE`이 있어도 실패한다.
- [ ] 나머지 모든 타일이 유효해도 하나의 `TILE_NONE`으로 실패한다.
- [ ] 실패 결과에 `Map`이 존재하지 않는다.

## 15. 구조적으로 유효한 경계 사례 테스트

- [ ] `1 x 1` FLOOR 맵은 구조 검증에 성공한다.
- [ ] `1 x 1` WALL 맵은 구조 검증에 성공한다.
- [ ] 모든 칸이 WALL인 직사각형은 구조 검증에 성공한다.
- [ ] 한 행과 여러 열로 된 맵은 구조 검증에 성공한다.
- [ ] 여러 행과 한 열로 된 맵은 구조 검증에 성공한다.
- [ ] 전부 WALL인 맵의 전투 가능성은 이 단계에서 판단하지 않는다.

## 16. 기존 Map 질의 회귀 테스트

- [ ] `(0, 0)`이 범위 안이다.
- [ ] 우하단 마지막 좌표가 범위 안이다.
- [ ] `x`가 너비와 같은 좌표는 범위 밖이다.
- [ ] `y`가 높이와 같은 좌표는 범위 밖이다.
- [ ] 음수 `x`는 범위 밖이다.
- [ ] 음수 `y`는 범위 밖이다.
- [ ] 음수 좌표에서 컨테이너 접근이 발생하지 않는다.
- [ ] 범위 밖 `TileAt()`은 `TILE_NONE`을 반환한다.
- [ ] 범위 밖 `IsWalkable()`은 `false`를 반환한다.

## 17. 생성 결과 계약 테스트

- [ ] 성공 상태에는 항상 `Map`이 존재한다.
- [ ] 실패 상태에는 항상 `Map`이 없다.
- [ ] 성공 상태와 빈 포인터를 조합할 수 없다.
- [ ] 실패 상태와 유효한 포인터를 조합할 수 없다.
- [ ] 실패 결과에서 소유권을 꺼낼 수 없다.
- [ ] 성공 결과에서 소유권을 한 번 이동할 수 있다.
- [ ] 소유권 이동 후 원본 결과는 `Map`을 소유하지 않는다.

## 18. unique_ptr 소유권 테스트

- [ ] `MapFactory` 결과가 생성 직후 `Map`을 소유한다.
- [ ] 임시 전투 상태가 `Map` 소유권을 이동받는다.
- [ ] 이동 후 생성 결과는 더 이상 소유하지 않는다.
- [ ] 새 소유자가 기존 질의 함수를 정상적으로 사용할 수 있다.
- [ ] `Map` 소유자가 파괴될 때 수동 해제 없이 정리된다.
- [ ] 원시 `delete`를 직접 호출하지 않는다.
- [ ] 같은 `Map`을 두 `unique_ptr`가 동시에 소유하지 않는다.
- [ ] Renderer와 질의 시스템은 소유권 없이 읽기 전용으로 접근한다.

## 19. 테스트와 디버그 정책

- [ ] 테스트를 위해 빈 `Map`을 허용하지 않는다.
- [ ] 모든 테스트 맵도 `MapFactory`를 통해 생성한다.
- [ ] 구조 검증 실패는 결과 상태로 확인한다.
- [ ] 내부에서 절대 깨지면 안 되는 가정만 `assert` 후보로 삼는다.
- [ ] `assert`를 재생성 요청이나 유저 오류 처리에 사용하지 않는다.
- [ ] 출시 빌드에서도 잘못된 `Map`이 외부에 제공되지 않게 한다.
- [ ] 실패 데이터를 자동 수정해 테스트를 통과시키지 않는다.

## 24. 첫 구현 완료 판정

다음 흐름이 실제로 동작하면 이번 구현을 완료한다.

```text
정상 TileGrid 준비
-> MapFactory에 소유권 전달
-> 구조 검증 성공
-> TileLayout 생성
-> Map 생성
-> MapCreationResult 성공
-> unique_ptr<Map> 이동
-> 기존 Map 질의 기능 확인
```

다음 실패 흐름도 동작해야 한다.

```text
잘못된 TileGrid 준비
-> MapFactory에 소유권 전달
-> 구조 검증 실패
-> 구체적인 실패 상태
-> Map 없음
-> 부분 객체 외부 노출 없음
```
